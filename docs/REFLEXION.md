# Reflexión sobre desarrollo asistido por IA

La IA produjo la estructura del monorepo, la interfaz, la API, las reglas de pedidos y pagos, las pruebas y la documentación. Se comprobó automáticamente que el frontend compila y que siete pruebas de lógica y API pasan; también se verificaron `/health`, el catálogo, el frontend y el rechazo de rutas anónimas.

La decisión de desarrollar una tienda de libros electrónicos provino de la sección 13 de la guía y fue confirmada por el estudiante. Para cubrir el requisito de envíos, la aplicación admite también ejemplares impresos con dirección y guía de seguimiento. Los importes, el stock y los permisos se validan en el servidor.

El catálogo de cinco libros utiliza títulos, editoriales, descripciones y precios ficticios creados para la demostración. Después de validar el catálogo, se generaron cinco ilustraciones originales con IA para sus portadas y se optimizaron como WebP locales. El título y las etiquetas siguen siendo HTML/CSS para evitar errores de texto dentro de la imagen. Los tres archivos de descarga digital son textos originales de muestra. La procedencia y los prompts están en [Portadas IA](PORTADAS_IA.md).

SQLite permitió desarrollar y probar las reglas del sistema de manera local. Después se preparó un adaptador Mongoose para el clúster Atlas creado por el estudiante, con selección por `MONGODB_URI`; Mongoose y la cadena privada ya están configurados. Se detectó primero una falla DNS con el URI SRV y luego Atlas informó que la IP actual no estaba autorizada. Tras cambiar al URI estándar y agregar la IP, `seed` terminó correctamente desde el PowerShell del estudiante y Data Explorer confirmó cinco documentos. Una prueba HTTP real contra la API conectada a Atlas confirmó registro ficticio, pedido mixto, idempotencia, reserva de stock, cancelación y devolución de stock. TestSprite aprobó tres casos públicos por túnel local. El pago Sandbox y el despliegue Railway no se han verificado todavía; la verificación de la cuenta PayPal quedó bloqueada temporalmente. Presentar esas partes como terminadas sería incorrecto.

Antes de entregar, el estudiante debe añadir aquí sus propias observaciones personales: qué decisiones tomó al revisar el resultado, qué aprendió al ejecutar las pruebas y qué corregiría en una siguiente iteración. No se atribuyen al estudiante acciones que no constan en el trabajo realizado.
